# tg-net-bot

Telegram-бот для ручной проверки серверов и настройки пользовательских алертов. Сервер можно проверить без сохранения или добавить в список. Бот выполняет проверки ICMP/TCP/HTTP и обращается к Cheburcheck, если настроенная проверка алерта обнаруживает недоступность сервера. Сервер задаётся доменом, IPv4 или IPv6.

## Установка на сервер

```sh
sh -c "$(curl -fsSL https://raw.githubusercontent.com/theillarion/tg-net-bot/1518c655a115a70ca1743d2d1c37a40530247a2e/install.sh)"
```

Команда загружает проверенную версию установщика по SHA коммита, чтобы CDN-кеш ветки `master` не отдал предыдущую версию сразу после обновления. Установщик спросит каталог установки; по умолчанию используется текущая папка (`.`). Нажми Enter, чтобы оставить её. Скрипт запросит токен бота, разрешённые ID пользователей Telegram и необязательный прокси, затем соберёт и запустит сервис через Docker Compose. Запускай его из пустой папки или из уже клонированного репозитория. Чтобы использовать форк, укажи `REPO_URL`.

## Запуск из клона репозитория

```sh
git clone https://github.com/theillarion/tg-net-bot.git
cd tg-net-bot
cp .env.example .env
# Укажи TELEGRAM_TOKEN и TALAGRAM_ALLOW_USERS в .env
docker compose up -d --build
```

Переменная `TALAGRAM_ALLOW_USERS` намеренно написана именно так, как было запрошено. Укажи через запятую числовые ID пользователей Telegram. Узнать свой ID можно с помощью Telegram-бота для просмотра ID; разрешай доступ только нужным аккаунтам. В `TELEGRAM_PROXY` можно указать HTTP(S)- или SOCKS5-прокси, например `socks5://host:port`. Переменная `DATABASE_PATH` задаёт путь к базе SQLite. Compose подключает каталог `./data`, поэтому база сохранится после пересоздания контейнера.

## Локальный запуск CLI

В бинарном файле есть команды для ручных проверок и запуска бота:

```sh
go run ./cmd/tg-net-bot check --method tcp --arg 443 example.com
go run ./cmd/tg-net-bot check --method icmp 2001:db8::1
go run ./cmd/tg-net-bot block example.com
go run ./cmd/tg-net-bot serve
```

Команда `check` выводит JSON в stdout — его можно передать, например, в `jq`. Команда `block` выводит результат проверки Cheburcheck по базе и через probe-узлы. Команда `serve` читает настройки из переменных окружения. Справка по командам: `go run ./cmd/tg-net-bot --help`.

## Структура проекта

```text
cmd/tg-net-bot/       точка входа CLI и регистрация команд
internal/app/         сборка приложения и управление его жизненным циклом
internal/config/      загрузка и проверка настроек из окружения
internal/domain/      типы серверов и алертов
internal/monitor/     сценарии работы с серверами и алертами
internal/checker/     проверки доступности ICMP, TCP и HTTP
internal/cheburcheck/ HTTP/SSE-клиент Cheburcheck
internal/storage/     SQLite-репозиторий и схема базы данных
internal/telegram/    адаптер Telegram Bot API и обработчики бота
```

В `internal/monitor` определены небольшие интерфейсы для хранения данных, сетевых проверок, проверки блокировок и отправки уведомлений. В `internal/app` конкретные адаптеры связываются через конструкторы.

## Интерфейс Telegram-бота

После команды `/start` бот показывает постоянное меню с кнопками. Через него можно запускать разовые проверки доступности и Cheburcheck, управлять серверами и настраивать алерты — команды запоминать не нужно. Мастер настройки алерта предложит выбрать сервер, метод проверки, при необходимости порт или протокол, а затем периодичность, которую задаёт пользователь. У сохранённых серверов и алертов есть встроенные кнопки действий.

### Команды (необязательно)

- `/start` — открыть меню и показать справку.
- `/check <сервер> [icmp|tcp|http] [порт-или-URL]` — проверить сервер без сохранения или обратиться к сохранённому серверу по имени. Сервер можно указать по IP или домену. Для TCP по умолчанию используется порт 443; для HTTP — `https://<сервер>`.
- `/block <сервер>` — вручную проверить сервер через Cheburcheck, независимо от того, сохранён он или нет. Можно указать IP или домен.
- `/add <имя> <IP-или-домен>` — сохранить сервер. Если отправить просто `/add`, бот проведёт через добавление пошагово.
- `/hosts` — показать сохранённые серверы.
- `/remove <имя>` — удалить сервер.
- `/alert <имя> <icmp|tcp|http> <интервал> [порт-или-URL]` — создать алерт для сохранённого сервера. Например: `/alert edge tcp 5m 443`. Когда проверка обнаружит переход в состояние «недоступен», бот запросит результат Cheburcheck и отправит уведомление. При восстановлении сервера бот сообщит об изменении состояния.
- `/alerts` — показать правила алертов.
- `/alert_remove <ID-правила>` — удалить правило алерта.

Для интервалов используется формат Go duration: `30s`, `5m`, `2h`. Пользователь задаёт интервал отдельно для каждого алерта в Telegram; общей настройки частоты проверок нет. Уведомления отправляются при переходе между состояниями. Первая успешная проверка только задаёт исходное состояние и не вызывает уведомление. У каждого правила свои метод и периодичность, а также необязательный порт или URL. Несохранённые серверы тоже можно проверять вручную. Данные SSH-доступа бот не запрашивает и не хранит.

Для ICMP в Compose добавлено разрешение `NET_RAW`; при этом удалённая сеть может блокировать ping. Проверка TCP устанавливает, принимает ли порт подключения. Проверка HTTP выполняет GET-запрос: коды ответа ниже 500 считаются доступными. Cheburcheck вызывается только после неудачной проверки, заданной в правиле алерта.

Серверы, методы проверок, отдельные интервалы алертов и последнее известное состояние хранятся в SQLite. По умолчанию база находится в `./data/tg-net-bot.sqlite`. В ней используются отдельные таблицы `targets` и `alerts`; внешний ключ удаляет связанные алерты при удалении сервера. Чтобы сохранить настройки и правила, делай резервную копию каталога `data/`.
